# 空间记忆引擎 —— 设计文档

> 状态：v0 纯内存 ✅，v1 持久化 ✅，v2 压缩+时间查询 ✅
> 更新：2026-11-20

## 1. 定位

为具身机器人提供"记得住、查得快、掉电不丢"的空间记忆存储：
把检测观测按**对象**持久化，支持空间 / 时间 / 语义查询，通过 ROS2 接入机器人。
v3 规划：**物体级开放词汇**——每个物体存 CLIP 特征（1KB），支持自然语言查询（`query_text`），
不做像素级特征（边缘算力不可行）。

不做：SLAM 本体、检测模型训练、3DGS 渲染、大模型 VLA。

## 2. 架构总览

```
┌──────────── 写入流 ────────────┐
相机 → YOLO(NPU) → 检测列表 → engine.add_observation
                                  │
                      ┌───────────┴───────────┐
                      ▼                       ▼
                内存（权威）             SQLite（持久化）
                ├ 对象池                 ├ 对象表（当前状态）
                ├ 网格索引               └ 观测表（历史流水）
                ├ ID→槽位映射
                └ 类别索引
┌──────────── 查询流 ────────────┐
调用方 → query_radius → 只读内存索引 → QueryResult 快照
┌──────────── 恢复流（v1）────────┐
进程启动 → SQLite → 重建内存索引
```

分层原则：**内存索引是查询权威，SQLite 是事实源但不在关键路径上。**

## 3. 数据流

### 3.1 写入流（每帧 10~20 次）

```
add_observation(obs)                   耗时 ~3µs
│
├─① 网格查候选
│   用 (x,y,z) 算出所在格子，扫周围 27 格
│   得到 ~20 个候选槽位
│
├─② 三重过滤（在候选上做，不碰全表）
│   类别相同？ 时间窗内（5s）？ 距离 <0.5m？
│   取最近的候选
│
├─③ 分支
│   命中 → 更新实体：位置、last_seen、观测次数+1、置信度滑动平均
│          若移动跨格：从旧格子删除 → 插入新格子（防幽灵）
│   未命中 → 新建：分配槽位 → 写实体字段 →
│            入网格 → 记 ID 映射 → 进类别索引
│
└─④ [v1] 变更进写队列（不阻塞主线程）
     后台每 50ms 或攒 100 条 → 一个 SQLite 事务批量提交
     一次 fsync（6.13ms）摊到 100 条 = 61µs/条
```

关键点：检测阶段 30.6ms/帧，写入阶段 ~30µs/帧——存储对整条链路影响 < 0.1%。

### 3.2 查询流

```
query_radius(center, 1.5m, label=cup)   耗时 ~40µs
│
├─ 网格定位：覆盖查询球的格子（约 27 格）
├─ 遍历槽位 → 精确距离过滤
├─ 类别过滤
└─ 拷贝成 QueryResult 列表返回（值快照）
```

查询永远不读磁盘；磁盘只用于启动恢复和冷数据查询（历史观测）。

### 3.3 恢复流（v1）

```
启动
├─ 打开 SQLite → WAL 自动前滚（重放已提交未落盘事务）
├─ 读对象表全部行 → 重建 EntityPool / ID映射 / 类别索引
├─ 逐实体重建网格索引
└─ 完成（目标 < 2s），接新数据
```

## 4. 三份数据的角色

| 数据 | 位置 | 回答什么问题 | 权威性 |
|---|---|---|---|
| 对象池 + 网格索引 | 内存 | "现在周围有什么" | 查询权威 |
| 对象表 | SQLite | 重启后"有什么" | 恢复权威 |
| 观测段表 | SQLite（驻留段聚合） | "上周三杯子在哪" | 历史权威 |
| 写队列 | 内存 | 待落盘变更 | 易失（最多丢 50ms） |

## 5. 一帧的完整时间账（实测）

```
16:00:00.000  相机出帧
16:00:00.030  YOLO 检测完成（30.6ms，NPU）
16:00:00.030  10 个检测 → 10 次 add_observation（共 ~30µs）
16:00:00.080  后台批量提交 SQLite（50ms 周期，fsync 与主线程并行）
下一帧照常进行
```

同步路径上没有任何磁盘操作——30 FPS 全链路不掉帧的基础。

## 6. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 持久化后端 | SQLite WAL | 崩溃恢复内建（前滚）、单文件零运维、ACID；实测 37.8k rows/s 批量写 |
| 为什么不自研存储引擎 | 不自研 WAL | 恢复可靠性成本高；差异化在内存索引与系统设计 |
| 热点索引 | 自研网格哈希（1m） | O(1) 定位，10 万对象 P99 47µs |
| 对象存储 | 连续 vector + free list | 缓存友好、O(1) 分配；不用 map |
| 并发模型 | 单写队列 + 内存只读查询 | 无锁竞争；WAL 读写并行 |
| 对象 ID | 单调 ID + 关联，不用哈希 | 移动后 ID 稳定，可跨会话追溯 |
| 观测组织 | 按小时分段 | 便于压缩与整段清理 |
| ROS 耦合 | 零依赖核心库 | ROS2 节点只做消息转换（v3） |

## 7. 性能基线（Orange Pi AIpro，昇腾 310B 4×A55 @1.6GHz）

| 指标 | 实测 |
|---|---|
| 半径查询 P99（10 万对象，r=1.5m） | 47~50 µs（v0 / v1） |
| 查询 P50 / max | 37~39 µs / 86 µs |
| 插入吞吐（纯内存，含关联） | 32.8 万/秒 |
| **持久化写入吞吐（含批量 flush）** | **18,717 /秒**（v2 含段合并） |
| **恢复时间（10 万实体）** | **438 ms** |
| **观测压缩比（静止场景）** | **294:1**（1 万观测 → 34 段） |
| **时间范围查询 P99** | **162 µs** |
| 单物体轨迹查询 | 216 µs（16 段） |
| **kill -9 崩溃恢复** | **5/5 轮通过**（每轮 6000 条写入全部恢复，integrity ok） |
| 特征向量检索（v3a，1 万 × 512 维 top5） | **P50 12.2 ms / P99 12.3 ms** |
| CLIP 视觉塔推理（v3b，224×224） | **18.9 ms/次**（实机复测，与可行性验证一致） |
| 内存占用 | 16.6 MB / 10 万实体（≈166 B/实体） |
| SD 顺序写 / 4K fsync | 30.2 MB/s / 6.13 ms |
| SQLite 批量 1000 写入 | 37,857 rows/s |
| NPU YOLOv10n（640×640） | 30.6 ms/帧（32.7 FPS） |
| **NPU CLIP ViT-B/32 视觉编码（224×224）** | **18.85 ms/次（53 FPS）**（v3 可行性验证） |

行业对照：Yggdrasil（2026）2~127 µs（桌面/嵌入式）——本引擎单点指标处于同一量级，硬件更弱。

## 8. 演进路线

| 阶段 | 内容 | 验收 |
|---|---|---|
| v0 ✅ | 纯内存引擎（网格+对象池+关联） | P99 < 500µs，10 单测 |
| v1 ✅ | SQLite WAL + 观测表 + 启动恢复 | 持久化 24k/s，恢复 452ms，12 单测 |
| v2 ✅ | 观测压缩（驻留段）+ 时间查询 API | 压缩比 294:1，时间查询 P99 162µs，16 单测 |
| v3 | 开放词汇（物体级 CLIP 特征 + query_text 向量检索）+ rclcpp 节点 + 摄像头接入 | ≥15 FPS 端到端，query_text P99 <20ms，Recall@5 >80% |
| v4 | ReSpaceBench 评估 + 机械臂联动 | 重访一致性、抓取闭环 |
